## Remaining problems

1. **Medium — some real failures are reported as done.** `ProtocolRules.failed` misses three replies that allowed steps actually return:
   - "No app called Spotfy on the phone." (`Apps.open`): `no \w+ app` needs a word before "app".
   - "No light called bedroom. He has: …" (`Lights.set`)
   - "Need a length in minutes." (`set_timer`)

   With `taps=false`, `Music.play` can also return "Opened workout playlist in YouTube Music." while nothing plays, and that counts as done too. So he can hear "Gym protocol: open Spotify, workout playlist." when neither happened.
   Repro: `ProtocolRules.failed("No app called Spotfy on the phone.")` → false (test `realFailureRepliesAreCaught`).
   Fix:
   - In `ProtocolRules.failed`, add `|no (app|light) called|^need an? ` to the regex. The anchored `^need an? ` doesn't catch "He'll need to unlock".
   - In `Music.kt`, change `if (!taps) return "Opened $query in $name."` to `if (!taps) return "Couldn't start $query; it's open in $name."`

2. **Medium — "work out" runs the dash protocol.** He saves "workout". On-device speech often writes "work out protocol". `ProtocolRules.match` compares exactly, so Reflex misses and it goes to Claude, which calls `run_protocol("work out")`. `CustomProtocols.run` misses again, and `Protocols.run` hits `name.contains("work")`, so it runs **dash**: driving mode on, Dasher opens, music starts. The same thing happens with "study time" vs "studytime".
   Repro: `ProtocolRules.match("work out protocol", listOf("workout"))` → null (test `spacingVariantsStillMatch`).
   Fix: compare names with spaces removed in both places.
   - `ProtocolRules.match`: `return names.firstOrNull { it == said } ?: names.firstOrNull { it.replace(" ", "") == said.replace(" ", "") }`
   - `CustomProtocols`, add `private fun key(all: JSONObject, name: String): String? = all.keys().asSequence().toList().let { ks -> ks.firstOrNull { it == name } ?: ks.firstOrNull { it.replace(" ", "") == name.replace(" ", "") } }`
   - In `run`: `val all = load(Prefs(context)); val steps = key(all, name)?.let { all.optJSONArray(it) } ?: return null`
   - In `delete`: use `val k = key(all, name) ?: return "There's no protocol called $name, sir."` then `all.remove(k)`.

3. **Low — natural names are refused as "built in".** "movie night", "date night", "game night" and "bedroom" all get "That one's built in, sir. Pick another name." They aren't built in, and the spec only protects dash, baby, home and goodnight. Nothing needs this now: `Protocols.run` runs the custom protocol first, so his own "movie night" would run correctly.
   Repro: `ProtocolRules.check("movie night", gym, emptySet())` → refused (test `naturalNamesAreAllowed`).
   Fix: anchor the pattern so it only matches whole built-in names:
   ```kotlin
   private val BUILT_IN_PATTERN = Regex("^(good ?night|bed ?time|bed|sleep\\w*|sleep time|night( ?time| feed)?|feed(ing)?( time)?|baby( time)?|dash(ing)?|work( out)?|home( time)?)$")
   ```
   This still refuses everything in the builder's `builtInAliasesProtected` ("bedtime", "night feed", "work out", "sleepy") and still allows "workout" and "homework".
