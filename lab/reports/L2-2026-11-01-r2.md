## Test-change ruling ("4.05 dollars" → "$4.05")
**Acceptable, not a weakened test.** Both changed assertions still check the same number, the same position in the sentence and the same surrounding words; only the money format changed. The spec asks for numbers written to be spoken and doesn't fix a format, and "$4.05" is how the rest of the app already speaks money (`Earnings.money`), which Android TTS reads as "four dollars and five cents". This also resolves the round-1 problem it replaces. The only remaining risk is the on-phone Piper voice, which the whole app already shares. I added `l2_r2_moneyIsSpokenForm` to pin the format.

## Remaining problems
1. **Medium (real-world risk) — any "N min" on the whole Dasher screen can be taken as the trip time.** The screen text is joined and the first in-range "N min" wins, so a banner like "Dash ends in 45 min" ahead of the card's "18 min" gives about 11 an hour → "I'd pass." on a great offer. Repro: `OfferMath.line(OfferMath.parse("Dash ends in 45 min | $8.50 | 2.1 mi | 18 min | Accept", 19*60)!!, 2.0, 20.0)` → "…about 11 an hour. I'd pass."
   Fix (verified, all 27 tests pass): in `OfferMath.minutes`, only accept a text item that is just a duration:
   ```kotlin
   all.split(" | ").mapNotNull { Regex("^\\s*(\\d{1,3})\\s?(?:min|mins|minutes)\\s*$", RegexOption.IGNORE_CASE).find(it) }
       .map { it.groupValues[1].toInt() }.firstOrNull { it in 3..120 }?.let { return it }
   ```
2. **Low — "100 cents a mile".** $6.99 for 7 miles → rate 0.9986 → "100 cents a mile". Fix in `OfferMath.line`: `val rateWords = if (Math.round(rate * 100) < 100) "${Math.round(rate * 100)} cents" else money(rate)` → "$1 a mile".
3. **Low — a rejected hourly minimum still saves the per-mile change.** In `setRule` the range check comes after `perMile` is saved, so "2.5 a mile and 2 an hour" saves 2.5 a mile, skips `on`, and replies as if nothing changed. Fix: move `if (perHour != null && perHour !in 5.0..100.0) return …` to the first line of `setRule`, before any `edit()`.
