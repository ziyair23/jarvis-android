## Problems

1. **High (acceptance test 2) — nested protocol gets the wrong refusal.**
   Repro: `ProtocolRules.check("gym", listOf("phone_control","run_protocol"), emptySet())` returns "I can only put phone, music…". The spec requires "I can't put texting, calls or screen taps in a protocol, sir." Test `ProtocolRulesSpecTest.at2_everyForbiddenToolGetsTheSpecLine` fails.
   Fix, in `ProtocolRules.kt`:
   ```kotlin
   private val PEOPLE_OR_SCREEN = setOf(
       "send_text", "call", "reply_message", "answer_call", "decline_call", "screen_tap", "screen_type", "screen_action",
       "run_protocol", "phone_task"
   )
   ```
   The builder's test `ProtocolRulesTest.refusesNestedAndUnknownTools` asserts the old, off-spec line for `run_protocol`, so correct its first line to match the spec: `assertEquals("I can't put texting, calls or screen taps in a protocol, sir.", ProtocolRules.check("gym", gym + "run_protocol", emptySet()))`. That aligns the test with the spec and does not weaken it. Keep the `log_expense` line as is.

2. **High (Safe) — a `play_music` step can tap the screen.** The spec says "Never: … tapping or typing on screen". When the assistant play request doesn't start the song and the phone is unlocked, `Music.play` falls back to `JarvisAccess.tap((song ?: query))`, a loose match (exact, then starts-with, then contains) on whatever window is in front. It then taps "Play"/"Resume"/"Play all"/"Shuffle", all without checking that the front app is the music app. In a protocol this runs hands-free from a two-word voice match with no Claude in the loop. A preceding `open_app` step (e.g. Instagram) or a slow Spotify launch can leave another app in front. I found no path where it could send, buy or post. It is still screen tapping, and that is on the protocol "Never" list.
   Repro (by reading): protocol `[open_app Instagram, play_music "workout"]`, phone unlocked, the play-from-search intent doesn't start within 7 s → `Music.play` step 2 → `JarvisAccess.tap("workout")` on `rootInActiveWindow`.
   Fix (two parts):
   - `CustomProtocols.run` (Iron.kt), replace the step call with:
     ```kotlin
     val inp = JSONObject((st.optJSONObject("input") ?: JSONObject()).toString())
     if (tool == "play_music") inp.put("no_screen", true)
     try { out.add(actions.run(tool, inp)) }
     ```
   - `Actions.run` "play_music": `Music.play(context, pkg, name, q, input.optString("song").ifBlank { null }, taps = !input.optBoolean("no_screen"))`. In `Music.play`, add the parameter `taps: Boolean = true` and change `val access = JarvisAccess.on(context)` to `val access = taps && JarvisAccess.on(context)`. Also change the no-access return to `if (!taps) return "Opened $query in $name."` before the existing "can't press play without screen control" line.
   - Recommended for the non-protocol path too: before each `JarvisAccess.tap` in `Music.play`, require `JarvisAccess.me?.rootInActiveWindow?.packageName == pkg`.

3. **Medium (Fast and short, Feel) — running a protocol speaks the raw tool outputs.** `CustomProtocols.run` returns `out.joinToString(" ")` of every tool result, and the Reflex path speaks it word for word. Those strings were written for Claude to summarise. Gym gives "Do Not Disturb on. Playing Workout Mix on YouTube Music. Done: Bedroom, Living room." Worse cases get read out to him: "He needs to allow quiet mode: open the Jarvis app and tap Allow quiet mode.", "Tell him plainly he'll need to tap it this once.", and a `get_weather` or `status_report` step adds 40–60 words. The spec says "answers in one short line".
   Fix: add to `ProtocolRules`
   ```kotlin
   fun runLine(name: String, done: List<String>, failed: List<String>, info: List<String>): String {
       val t = name.replaceFirstChar { it.uppercase() }
       val s = StringBuilder(if (done.isEmpty()) "$t protocol" else "$t protocol: ${done.joinToString(", ")}.")
       if (failed.isNotEmpty()) s.append(" ${failed.joinToString(" and ").replaceFirstChar { it.uppercase() }} didn't work.")
       info.forEach { s.append(" ").append(it) }
       return s.toString().trim()
   }
   ```
   In `CustomProtocols.run`, for each step: if `tool in setOf("get_weather","calendar_events","status_report","list_read")`, add the result to `info` (for weather use `Weather.now(context)` instead of the 2-day `report`). Otherwise, if the result matches `Regex("couldn't|can't|didn't|wouldn't|needs to|no lights|not |only \\d+ of|that didn't work", IGNORE_CASE)`, add `ProtocolRules.describe(tool, detail(inp))` to `failed`, else to `done`. Return `runLine(...)`. Log the raw failures with `Problems.log` so nothing is lost. Add a unit test that `runLine("gym", listOf("quiet","workout playlist","lights off"), emptyList(), emptyList())` gives "Gym protocol: quiet, workout playlist, lights off."

4. **Medium (Hands-free, Cost) — after a protocol starts music, Jarvis keeps listening over it.** `JarvisService.handle` clears `brain.lastTools` for Reflex hits, so the "he asked for music: let it play" check never sees `play_music`. `Hit` is built with `endConvo = false`, so the conversation stays open with the song playing. Lyrics can then be heard as a follow-up and sent to Claude, which costs a call and could trigger a misfire.
   Repro (by reading): "gym protocol" → Reflex Hit (endConvo false) → `inConvo` stays true → `nextTurn(keep = true)` → mic open over the workout playlist.
   Fix in `Reflex.match`: `ProtocolRules.match(t, CustomProtocols.names(c))?.let { n -> CustomProtocols.run(c, n)?.let { return Hit(it, endConvo = true) } }`. A protocol is a one-shot command. He can say "Jarvis" again.

5. **Low — `run_protocol`'s `name` field still says "dash, baby, home or goodnight".** Claude may be reluctant to pass "gym" through it when the instant path misses (e.g. "run the gym one"). Fix in `Actions.kt`: `props("name" to str("dash, baby, home, goodnight, one of his own saved protocols, or 'list'"))`.

6. **Low — deleting a built-in says it doesn't exist.** "Delete the dash protocol" → "There's no protocol called dash, sir." Fix in `CustomProtocols.delete`, first line after `name`: `if (name in ProtocolRules.BUILT_IN) return "That one's built in, sir. It stays."`

7. **Low — the old built-in aliases can be taken by custom names.** Before L11, "bedtime protocol" and "sleepy mode" went to goodnight, and "night feed protocol" went to baby (substring match in `Protocols.run`). Now he can save a custom "bedtime" or "night feed", and `Protocols.run` runs the custom one first. The spec only protects the four names, so this doesn't fail AT4, but it can surprise him. Fix: in `ProtocolRules.check`, also refuse when `Regex("good ?night|sleep|bed|dash|work|baby|night|feed|home").containsMatchIn(name)` (the same patterns `Protocols.run` uses). Keep the same "That one's built in, sir. Pick another name." line.

8. **Cosmetic.** In `Iron.kt` the KDoc "Named routines, like the films…" now sits above `CustomProtocols` instead of `Protocols`. Move it down. In `Reflex.kt`, `timer(c, t)?.let` is indented 16 spaces instead of 8.

## Cost
The instant path is free. Saving costs one Claude call. The two new tool schemas add about 300 tokens to the tools list, which is already cached (`cache_control` on the last tool in Brain.kt). That's well under $1 a month extra.

## Safety and secrets
- No keys or secrets added. Protocols are stored only in SharedPreferences (`custom_protocols`).
- No new permissions.
