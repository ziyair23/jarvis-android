3. Catch-up calls `ask(held = ...)` with the phone tool list empty (only server-side web search, which can't act on the phone). PASS.
4. Each held item asked separately, joined by `Held.combine`; "Signal's back, sir." once. PASS.
5. Newest 3, repeat moves to newest, >45 min dropped silently. PASS (tested).
6. Claude failing at catch-up returns "", falls to `Held.reminder` in his words. PASS.
7. `prefs.addTurn("user", held ?: text)`. PASS.

## Scenarios
- **7 AM, car Bluetooth, dead spot on the highway:** "Jarvis, what time does Costco close?" → instant "No signal, sir. I'll come back to that when it's back." → signal returns → 2.5 s later, if he isn't mid-turn, "Signal's back, sir. Costco closes at 8:30." without the alert chime. Good.
- **Evening shift, signal bars but no data:** if Android still says the network is validated, worst case ~6 s connect timeout + 3 s HEAD before the held line ("Still on it, sir." may play at 7 s). If the drop happens mid-answer, up to 30 s read timeout + 3 s. Acceptable, not instant.
- **At home, Govee/Google Home on Wi-Fi without internet:** light reflexes run before `ask`, unaffected.
- **Noisy car / mishears:** see problems 1–2.
- **No signal, follows up within 3 s:** follow-up goes the same path and is held. See problem 2.
- **Vague request offline:** held and answered later, fine.
- **Quiet mode:** catch-up goes to `Stealth.silentNote`. Good.
- **On a phone call when signal returns:** `sayFirst` turns it into a notification. Good.
- **Misfire check:** held "text Jess I'm late" is answered with no phone tools, so nothing can be sent late. Nothing in L8 texts, calls, buys or posts.

## Problems (none blocks PASS; fix 1 before Marcus relies on it)
1. **An [ignore] at catch-up is spoken back as a reminder.** Repro: no signal, follow-up window open, he tells a customer "have a good night" → held. Signal returns → Claude answers `[ignore]` → `ask` returns "" → `signalBack` puts it in `missed` → Jarvis says *"Signal's back, sir. You'd asked "have a good night". Say it again if you still want it."* The spec's reminder is for when Claude *can't be reached*, not for chatter.
   **Fix:** in `Held.kt` add `const val IGNORED = "\u0000ignored"`; in `Brain.ask` change `if (reply.contains("[ignore]", true)) return ""` to `if (reply.contains("[ignore]", true)) return if (held != null) Held.IGNORED else ""`; in `JarvisService.signalBack` loop: `if (r == Held.IGNORED) continue` before the `isBlank` check.
2. **Offline chatter gets the held line.** Online, a one- or two-word fragment or talk not meant for him is silently `[ignore]`d. Offline, every follow-up-window fragment ("yeah", "here you go") makes Jarvis say "No signal, sir…" out loud. **Fix:** in `Brain.ask`, both `Held.add` call sites for `held == null`: before holding, `if (followUp && text.trim().split(Regex("\\s+")).size < 3) return ""` (the service already treats "" as ignored).
3. Minor: with a Google voice key set (`prefs.ttsKey`), the held line is synthesized by `CloudVoice` with an 8 s connect timeout before falling back to the phone voice. Usually fails fast (no DNS), but on "bars, no data" it can wait. **Fix:** in `JarvisService.speak`, `val key = if (brain.isValidated()) prefs.ttsKey else ""`.
