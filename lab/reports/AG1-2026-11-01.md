# AG1: Jarvis's brain (agents) — test report, 2026-11-01

**Verdict: PASS** (with one open question for Marcus, below)

Branch `agents`, test builds 66 and 67 (prerelease, never auto-installed). Live talking was not exercised on a real phone.

## What was tested
- **Build:** full CI build of the release app on the branch (builds 66, 67): success.
- **Unit tests** (`AgentsTest`, run in CI before every build from now on): 9 tests, all pass.
  - every one of Jarvis's 51 skills has an owner (Jarvis or an agent); no agent claims a skill that doesn't exist
  - sending skills (texts, replies, calls, screen tasks) live only with the Phone agent and still require `confirmed`
  - the confirm flag an agent passes always equals Marcus's real yes (`CONFIRMABLE`)
  - Builder: settings are range-limited; models and keys can't be changed; an instruction that weakens confirm-before-send is refused; keys, the signing key, the build workflow and the tests themselves are off limits
  - Builder instant changes merge on top of his settings without touching the originals
- **Brain tab** in a real browser (Playwright, mocked phone): renders, rotates, tapping the Phone node opens its panel, recent jobs and learned notes show, Teach and the on/off switch reach the app, all other tabs still work. No script errors (only the Google font can't load in the test sandbox).
- **Code review** of the hand-off: Jarvis → agent is one call; a one-step job returns the skill's result straight to Jarvis (no second round), so the hand-off costs one small Haiku call (~1 s). Every hand-off and every skill an agent uses is written to the flight log and to the agent's run history.

## Problems found and fixed during testing
1. A confirmed text could stall if the agent's model forgot the confirm flag → flag now set from Marcus's real yes.
2. "Did music just play?" could match a song from minutes earlier and end a live chat early → now only counts skills used during this turn.
3. Every agent job spoke "On it, sir" → only phone and builder jobs (the slow ones) do.
4. The Builder could have edited its own tests → tests are off limits.
5. The dashboard kept timers running in the background → paused when the app isn't on screen.
6. Brain view: names overlapped when an agent passed behind another → back names fade.
