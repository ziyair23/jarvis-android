# L8 — No-signal mode — test report 2026-11-01

**Verdict: FAIL.** The app doesn't compile. `Brain.ask` got a new last parameter, `held: String?`, but `JarvisService.handle` still passes `onAck` as a trailing lambda. Kotlin binds a trailing lambda to the last parameter, so the build fails and none of the acceptance tests can pass on a phone. If that were fixed, the plain logic (`Held.kt`) and the tool-less catch-up would be good. Two spec problems would remain: a false "Signal's back, sir." (with the held request lost) while he is still in the dead spot, and API errors at catch-up getting spoken as the answer instead of the reminder.

## Problems

### 1. BLOCKER: the build breaks (trailing lambda now binds to `held`)
- **Repro:** `./gradlew assembleDebug` → `JarvisService.kt:652: argument type mismatch: actual type is '() -> Unit', but 'String?' was expected`. Reproduced with kotlinc 2.0.21. `HeldSpecTest.brainAskKeepsOnAckLast` fails.
- **Fix (Brain.kt):** keep `onAck` last:
  ```kotlin
  fun ask(text: String, followUp: Boolean = false, onSentence: ((String) -> Unit)? = null, held: String? = null, onAck: (() -> Unit)? = null): String {
  ```
  `signalBack` already uses `held = it.text` by name, so nothing else changes.

### 2. MAJOR: false "Signal's back, sir." while still in the dead spot, and the held request is lost
- **Repro:** 7:20 AM, cellular still shows as connected and VALIDATED (the usual case in a short dead spot). "Jarvis, what time does Costco open" → two timeouts → held line. The validated default network's `onCapabilitiesChanged` fires again when the link-bandwidth or signal-strength estimates change, and on cellular that happens every few seconds. `Held.count() > 0` + VALIDATED → `signalBack` 2.5 s later → `takeDue` empties the list → the catch-up call times out twice → "Signal's back, sir. You'd asked "what time does costco open"…" is spoken **while there is still no signal**, and the request is gone. The opposite also happens: if no capability change arrives, a request held on a "validated" network may never be answered.
- **Fix (JarvisService.kt + Brain.kt):** trigger only on a real down→up change, and make Android re-check the network when a call fails:
  ```kotlin
  @Volatile private var netDown = false
  private val signalWatch = object : ConnectivityManager.NetworkCallback() {
      override fun onLost(network: Network) { netDown = true }
      override fun onCapabilitiesChanged(network: Network, caps: NetworkCapabilities) {
          if (!caps.hasCapability(NetworkCapabilities.NET_CAPABILITY_VALIDATED)) { netDown = true; return }
          if (!netDown || Held.count() == 0) return
          netDown = false
          main.removeCallbacks(signalBack); main.postDelayed(signalBack, 2500)
      }
  }
  ```
  In `Brain.ask`, in the network-failed branch, before `Held.add`, add: `try { val cm = context.getSystemService(ConnectivityManager::class.java); cm.activeNetwork?.let { cm.reportNetworkConnectivity(it, false) } } catch (_: Exception) {}`. Android then re-checks the network, VALIDATED drops while the dead spot lasts, and it comes back (firing the callback once) when data really works. Also set `netDown = true` when an item is held with no network at all: give `Held` a `@Volatile var down` flag that `add` sets, and have the callback read it.

### 3. MAJOR (spec AT 4/6): API errors at catch-up are spoken as the "answer"
- **Repro:** signal returns while Anthropic is overloaded (529 twice), or rate-limited/out of credit. `brain.ask` returns "I'm a bit overloaded, sir. Give me a moment and ask again." `signalBack` only checks `startsWith("I can't reach")`/blank, so he hears "Signal's back, sir. I'm a bit overloaded, sir. Give me a moment and ask again." He isn't reminded what he asked, and the request is lost.
- **Fix (Brain.ask):** when `held != null`, any failure returns `""`:
  - catch branch: `if (held != null) return ""` before the "I can't reach" line;
  - after the retry block: `if (held != null && code !in 200..299) return ""`;
  - the key check at the top: `if (key.isBlank()) return if (held != null) "" else "I need my Claude key first…"`.

  In `signalBack`, build the line per item so one failure doesn't turn real answers into reminders:
  ```kotlin
  val answers = due.map { it to brain.ask(Held.prompt(it, System.currentTimeMillis()), followUp = true, held = it.text) }
  val ok = answers.filter { it.second.isNotBlank() }.map { it.second }
  val missed = answers.filter { it.second.isBlank() }.map { it.first }
  val line = if (ok.isEmpty()) Held.reminder(missed)
      else Held.join(ok) + if (missed.isEmpty()) "" else " " + Held.reminder(missed).removePrefix("Signal's back, sir. ")
  ```

### 4. MEDIUM (Fast): "network present but failing" waits up to ~61 s before the held line
- **Repro:** dead spot with cellular still attached. The connect timeout is 10 s, the read timeout 30 s, and it tries twice with 0.8 s between, so the held line comes 20–61 s later (the "Still on it, sir." ack plays at 7 s). The spec's whole point is "instead of failing after a long wait".
- **Fix (Brain.ask catch branch):** if the first failure is `java.net.UnknownHostException`, `java.net.ConnectException` or `java.net.SocketTimeoutException` and `voice.spoke` is false, don't retry. Call `reportNetworkConnectivity(..., false)` (problem 2) and hold right away: `if (held == null && !didSomething && retried == 0 && e is java.io.IOException && !online(validated = true)) return Held.add(...)`, where `online(validated)` also requires `NET_CAPABILITY_VALIDATED`. Optionally lower `connectTimeout` in `post()` to 6000.

### 5. MINOR: race with his own turn when signal returns
- **Repro:** the signal comes back just as he says "Jarvis, what's the weather". His `handle` thread and the `signalBack` thread both run `brain.ask`. `Prefs.addTurn` reads history, adds a turn and writes it back, with no lock, so one thread's turns can overwrite the other's, and his held words can vanish from history (AT 7). The spoken side is fine: `sayFirst` queues the catch-up in `pending` while `busy`.
- **Fix:** in `Prefs.kt`, `fun addTurn(...) = synchronized(Prefs::class.java) { …existing body… }`. In `signalBack`, if `thinking || busy`, re-post itself 4 s later instead of starting (`if (thinking || busy) { main.postDelayed(signalBack, 4000); return@thread }`, before `takeDue`).

### 6. MINOR: Live mode offline logs a fake problem every time
- **Repro:** Live on, no signal → `startLive` → websocket `onFailure` "Unable to resolve host" → `Problems.log("live talking failed…")` → fallback → held line. It works, but there's a ~0.5–1 s extra delay and the Problems list fills with noise during every dead spot.
- **Fix (JarvisService.handle):** skip live when offline: `if (quick == null && liveOK(wasQuiet) && brain.isOnline())` (make `Brain.online()` public as `isOnline()`).

### 7. MINOR (Feel): the catch-up line comes after an alert chime
`sayFirst` plays `Sfx.play("alert")` before every proactive line, the catch-up included. This was already the case before L8, but the "no beeps" standard applies. **Fix:** add a `chime: Boolean = true` parameter to `sayFirst` and pass `false` from the `ACTION_SAY` intent (`putExtra("chime", false)` in `signalBack`).

### 8. COSMETIC: KDoc comments moved off their functions
In `Brain.kt` the "Ask Jarvis something" KDoc now sits on `online()`. In `JarvisService.kt` the "Home Wi-Fi after being out…" KDoc now sits on `signalWatch`. Move each back above its own declaration.
