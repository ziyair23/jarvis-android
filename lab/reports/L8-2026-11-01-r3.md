## Problems

### 1. MAJOR (AT 8): a slow answer on a good network is treated as "No signal"
- **Repro:** full 5G, quiet mode, or Google Cloud voice / no Piper voice, so `onSentence == null` and the call goes through non-streaming `post()`. "Jarvis, who won the Seahawks game and what were the key plays?" → `realQuestion` → Sonnet, 700 tokens, web search (max 3). The server sends nothing until the whole answer is ready, often 20–30 s. Before L8 he got the answer (30 s read timeout). Now:
  1. At 20 s → `SocketTimeoutException` → the new branch → `reportBad()` + "No signal, sir. I'll come back to that when it's back."
  2. 30 s later the safety net → validated + reachable → Haiku catch-up → "Signal's back, sir. …" (false).
  3. The first Sonnet+search call has already been paid for server-side, so it's paid twice.

  `still_working_ms` (7 s, "Still on it, sir.") shows slow answers are expected here.
- **Fix (Brain.kt):**
  1. In `post()`, put back `c.connectTimeout = 6000; c.readTimeout = 30000`.
  2. Only hold on a first timeout when the network is really dead:
     ```kotlin
     if (e is java.net.SocketTimeoutException && retried == 0 && !didSomething && !reachable()) {
     ```
     A dead link is then held after 6 s (connect timeout) + 3 s probe, or 30 s + 3 s on a read timeout. A slow but working Claude answer goes back to the old retry behaviour. `HeldSpecTest.slowAnswerOnWorkingNetworkIsNotHeld` passes once both lines are in.

### 2. MINOR: expired items keep the 30 s poll going
`Held.count()` counts items older than 45 min, so with no network for hours (airplane mode, a basement shift) the `signalBack` re-post and its failing HEAD probe run every 30 s until a network returns. It's cheap: there's no wake lock, Handler time pauses in deep sleep, and it fails instantly. Still, it's work for nothing.
- **Fix (Held.kt):** add `@Synchronized fun pending(now: Long) = items.count { now - it.at <= EXPIRE_MS }` and use `Held.pending(System.currentTimeMillis()) > 0` in the `signalBack` re-post check (and in `onCapabilitiesChanged` instead of `count()`).
