## Problems (none blocking)
1. **(Works) Quick commands push the real topic out of the history.** `addTurn` keeps the last 40 turns of any kind. Each reflex adds 2 and each read-out message adds 1, so an evening shift of skips, volume changes and messages can evict a topic from 2–3 hours ago. Then "where were we?" says "Nothing on the go, sir." (and Claude loses it too). **Fix** in `Prefs.addTurn`, replacing the trim loop:
   ```kotlin
   val all = (0 until h.length()).map { h.getJSONObject(it) }
   var quickLeft = 10; var realLeft = 40
   all.asReversed().filter { if (it.optBoolean("q")) quickLeft-- > 0 else realLeft-- > 0 }.asReversed().forEach { trimmed.put(it) }
   ```
2. **(Safety note, not a break)** If the topic was an unanswered send confirmation ("…Want me to send it?"), the recap reads only the first sentence, and a "yeah" next goes to Claude with that old confirmation still last in the history. Nothing is sent without his "yes", so the ground rule holds. Still, a "yes" given hours later shouldn't count. **Fix:** in Brain's system prompt (or `Actions` send tools), add: "A confirmation to send is only valid within 2 minutes of asking; otherwise ask again."
3. Cosmetic: the phone's recogniser (Parakeet) writes capitals, so the recap shows "You'd asked: What time…" on the lock screen. The voice is unaffected. **Fix:** in `Recap.answer`, `asked.replaceFirstChar { if (asked.startsWith("I ")) it else it.lowercase() }`.
4. Minor: a topic from 1 AM asked about at 9 AM is "Earlier today,"; "Last night," would fit better. **Fix:** in `whenSaid`, `days <= 0L && a.get(Calendar.HOUR_OF_DAY) < 5 && n.get(Calendar.HOUR_OF_DAY) < 12 -> "Last night,"` before the "Earlier today," branch.
